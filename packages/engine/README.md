# Rootwise M1 Engine v0.2 — Source-labelled agricultural screening

Installable Python 3.10+ engine, with **six transparent scoring criteria**, three
strategy *options*, evidence/confidence and M3/M4 JSON contracts. The initial
case study is Devanahalli, Karnataka, but the engine itself is location-neutral.

**This is a decision-support prototype, NOT an agronomically validated planting
prescription or a prediction of crop yield or profitability.** The sources below
describe real literature crop values; environmental data, market prices and farm
management must be provided separately by M2/M3.

## Installation on Windows / VS Code

From `D:\Codes\rootwise\packages\engine`:

```powershell
python -m pip install -e ".[dev]"
python -m pytest -q
python scripts/make_examples.py
python scripts/show_scores.py
```

If you are merging this updated package over the old version, back up your
existing `rootwise_engine/data/crops.yaml` first if you made manual changes.
Copy the **contents** of `packages/engine/`, never an extra nested `engine` dir.

## What is implemented

- `models.py`: Pydantic models for eight crops, weighted priorities, sourced
  inputs, farming situation, market observations, recommendation, simulations.
- `data/crops.yaml`: 8 verified crop identities, UAS varieties, FAO/ICRISAT seasonal crop-water references
  (generic proxies labelled), FAO stage Kc, source-labelled feed quality
  for 7 crops. Horse gram feed crude protein and general seasonal water demand unverified -> `null`.
- `data/variety_profiles.yaml`: source-specific flowering milestones and
  duration, plus UAS PHG-9 and KKM-3 maturity. **NOT** five-stage phenology.
- `data/research_sources.md`: all sources, exact applied figures and limitations.
- `DATA_STATUS.md`: per-crop data coverage and a clear list of unfilled inputs.
- `data/criteria.yaml`: explicit six equations and their *Rootwise-defined*
  normalization targets. No claimed FAO `0–100` scores.
- `scoring.py`: exact six-criteria weighted lower-bound index. Unavailable
  criteria stay `null`; completeness is reported separately.
- `strategies.py`: three distinct focus choices, ranked using the *original*
  farmer priority scores, with deterministic tie breaks and warnings.
- `phase.py`: observed/sourced five-stage phenology, otherwise `unknown`.
- `vulnerability.py`: critical-stage moisture and heat threshold exceedances,
  observed bare-soil dates only; no unsupported claims from NDVI alone.
- `water.py`: FAO reference stage `ETc = sum(Kc × ET0)` only when all daily
  ET0 dates are present; never equates reference ETc with irrigation.
- `simulate.py`: historical p10/median/p90 over at least 3 valid years; rainfall
  what-if, optional heat threshold *counts* (never yield penalties without a
  calibrated impact function), and user-defined alert threshold.
- `evidence.py`: provenance, missing values, qualitative confidence, local-review flag.
- `api.py`: `recommend`, `simulate`, `field_status`; `data_loader.py`:
  `load_crops`, `load_criteria`, `load_glossary`, `load_variety_profiles`.
- `examples/`: four request/response JSON pairs regenerated from actual engine.
- `tests/`: integrity, equations, missingness, validation, statuses, simulation,
  strategy ranking. All test inputs generated by test code are **SYNTHETIC**
  software fixtures, never Devanahalli observations.

## Six criterion implementations

| Criterion | Inputs from source or user | Formula | Status without M2/M3 |
|---|---|---|---|
| Water use | FAO published ET demand; or M2 crop ETc, effective rain, irrigation | 100 × min(1, available water / ETc); without M2 a relative inverse demand index | Partial, non-site-specific |
| Forage value | Feedipedia feed-material crude protein (% DM) | 100 × min(1, CP% / 20%) | 7/8 quality indices; **not** forage volume |
| Nitrogen fixing | documented biological legume/nonlegume | 100 or 0 | 8/8 capability indices; not soil N credit |
| Erosion reduction | field/management RUSLE crop-specific C factor | 100 × (1 − C) | `null` until documented C for specific field/crop |
| Organic matter | measured dry residue tDM/ha and fraction actually retained | 100 × min(1, retained tDM/ha / 5) | `null` until quantity/practice known |
| Market suitability | dated farm/mandi price, yield, cultivation and transport costs | 100 × clip(ROI / 1) | `null` until complete priced scenario |

The numbers 20% CP, 5 tDM/ha and ROI=1 are explicit **algorithm policy
benchmarks**, not published universal agricultural cutoffs. You can review
and change them with an agricultural specialist, but report a model version.

## M3 API use

```python
from rootwise_engine.api import recommend, simulate, field_status
from rootwise_engine.models import RecommendRequest, SimRequest

request = RecommendRequest.model_validate({
    "field": {"region_id": "devanahalli", "lat":13.25, "lon":77.71},
    "priorities": {"water_use":80,"forage_value":60,"nitrogen_fixing":90,
                    "erosion_reduction":70,"organic_matter":70,"market_suitability":50},
    "climate": {"data_kind":"missing"}
})
response = recommend(request)
print(response.model_dump_json(indent=2))
print(field_status(request).model_dump_json(indent=2))
print([x.model_dump(mode='json') for x in simulate(SimRequest(recommendation=request))])
```

### M2 -> M1 input checklist

M2 sends `Climate` values with source URL, date coverage, `data_kind`, grid
resolution and notes: daily climate, `seasonal_effective_rainfall_mm`,
`seasonal_etc_by_crop_mm`, irrigation from farmer/field data, and historical
climates for multiple complete years. Effective rainfall is derived, not a
NASA measurement; ETc must match each candidate crop's actual sowing-to-harvest
window. Use separate crop fields if season windows differ.

M3 collects `FarmField` per-crop management inputs when available:
`cover_management_c_by_crop` values between 0 and 1 with source or field
measurement flag, `residue_dry_t_ha_by_crop`, `residue_retained_fraction`,
`market_by_crop` (price INR/quintal; dated, market, source; yield quintals/ha;
cultivation and transport costs), `sowing_date`, `current_crop_id`, and (only
if documented) `phenology_override_days` for 5 stages.

See [INTEGRATION.md](INTEGRATION.md) for exact request examples and safe tests.

### Warning about your existing local NASA smoke script

Your previous `scripts/test_devanahalli.py` is compatible with `recommend()`
and `simulate()` and can be rerun. Its 2025 June–September water estimates
remain **test assumptions** (same season for all crops, generic FAO ETc proxy)
and cannot validate crop recommendations. **No real NASA values are packaged**;
the script you downloaded earlier caches them on your own computer. M2 owns
production environmental data integration.
